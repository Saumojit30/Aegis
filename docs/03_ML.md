# 03 — MACHINE LEARNING SPECIFICATION

## 1. Prediction problem
| Item | Definition |
|---|---|
| Event | A meal start at time `t0` for one patient |
| Inputs | Static profile, 60-min history (glucose, HR, METs), anchor features, meal features, meal-time features |
| Output | `ΔG(k)` for k = 1…36 (5–180 min after `t0`), in mg/dL relative to `G(t0)` |
| Derived | Predicted peak, time-to-peak, iAUC, minutes above threshold, delayed-window mean (120–180 min), risk flag |
| Unit | mg/dL |
| Primary window | 0–120 min; delayed window 120–180 min |
DATA-DEPENDENT: window lengths confirmed in A1/A2.

## 2. Baselines (all evaluated, all logged)
| ID | Model | Purpose |
|---|---|---|
| B0 | Persistence: `ΔG = 0` | Floor |
| B1 | Population mean response curve (per meal type) | Meal-agnostic reference |
| B2 | Ridge regression on meal + static + anchor features → 36 outputs (or PCA coefficients) | Linear reference |
| B3 | Gradient-boosted trees (per output or on PCA coefficients) | Strong tabular baseline |
| B4 | Per-patient mean curve (uses patient's own earlier meals) | Personalisation reference |
Rule: the final model is chosen **by evidence on held-out patients**. If B3 wins, B3 ships and the deep model is reported as a negative result.

## 3. Deep-learning candidates
| Candidate | Verdict |
|---|---|
| GRU over 12-step history + MLP fusion | **Primary** — small, fast, adequate for short sequences |
| LSTM | Equivalent alternative; try only if GRU underperforms |
| Temporal CNN | Optional ablation |
| Transformer | **Excluded** — too little data (45 patients) |
Complexity budget: parameters in the tens of thousands, trainable on CPU in minutes.

## 4. Proposed architecture
```text
history sequence (glucose, mask, HR, METs, Δglucose) ──► GRU encoder ─┐
static patient vector ──► patient encoder (MLP) ──────────────────────┤
meal vector + fast/slow features ──► meal encoder (MLP) ──────────────┼─► fusion (concat + MLP)
anchor / time features ───────────────────────────────────────────────┘          │
                                                                                 ▼
                                                              structured meal head (§5) + residual MLP head
                                                                                 ▼
                                                                       ΔG(1..36) trajectory
```
Training and inference share `aegis/features` and `aegis/models`.

## 5. Meal-structure head (differentiator 6A)
**Structured variant (candidate "S"):**
1. From meal features compute slow fraction `φ = sigmoid(w·[fat_ratio, protein_ratio, fiber_per_carb] + b)` and delay `d = d0 + d1·fat_ratio` (bounded, learnable).
2. Build two basis curves over k: `B_fast(k; τ_fast)` and `B_slow(k; τ_slow, d)` (gamma-shaped, normalised).
3. Patient gain `K_p = softplus(f(fusion))`; trajectory part = `K_p · carbs_eff · [(1−φ)·B_fast + φ·B_slow]`.
4. Add a small residual MLP output for what the structure misses; L2 penalty on the residual so the structure carries the signal.

**Unstructured variant (candidate "U"):** MLP head directly to 36 outputs.

**Ablation A1:** S vs U vs B3 on identical splits. Report overall, T2D-only and **delayed-window** error. If S is not better, S is demoted to "feature engineering" in the story.

## 6. Input / output contract (frozen after A3)
| Group | Shape | Notes |
|---|---|---|
| `seq` | [12, 6] | glucose Δ from `G(t0)`, glucose mask, HR z-score, METs z-score, activity calories, Δglucose |

Exact dimensions are confirmed in A3 and written to `configs/schema.yaml`.

## 7. Training strategy
- **Loss:** weighted Huber on the trajectory with (a) higher weight for under-prediction when true ΔG is high, (b) a peak-aware term, (c) L2 on the residual head. Weights are configuration tuned on validation patients — not claimed as clinically derived.
- AdamW; ReduceLROnPlateau or cosine; early stopping on validation-patient loss; weight decay; dropout; gradient clipping.
- **Degradation augmentation:** randomly apply modules from `aegis/degradation` (§9) with probability p (config).
- Fixed seeds; 3 seeds for final candidates; report mean ± std.
- Hyperparameters: small random/grid search on validation patients; do not invent values.

## 8. Evaluation
| Metric | Definition |
|---|---|
| MAE / RMSE | on ΔG over 0–120, over 120–180, and over all 36 steps |
| R² | reported where meaningful (not primary) |
| Peak error | |peak_pred − peak_true| (mg/dL) |
| Time-to-peak error | minutes |
| iAUC error | relative and absolute |
| Risk event | precision, recall, F1, PR-AUC at the configured threshold; confusion matrix per group |
| Interval | empirical coverage and mean width per horizon (§10) |
Reporting rules: patient-level bootstrap 95% CIs; T2D-only table; **paired** comparison to B0/B3 over patients; no cherry-picking of folds.

**Stratified evaluation:** by patient, group, meal type, glucose range at `t0`, history completeness, number of personal meals used (K), degradation scenario.

**Error analysis protocol:** (1) list the 20 worst meals; (2) inspect by patient, meal type, macros, missingness; (3) test hypotheses with a targeted ablation; (4) log decisions.

## 9. Degradation (differentiator 6B)
Single module `aegis/degradation` used by training, evaluation and replay.
| ID | Scenario | Operation (on the pre-`t0` window) |
|---|---|---|
| D0 | none | identity |
| D1 | CGM dropout N min | mask glucose for the last N min (N ∈ {15, 30, 60}); `anchor_age_min = N` |
| D2 | CGM gaps | random masking of glucose points with rate r ∈ {0.2, 0.5} |
| D3 | HR/METs missing | zero + mask HR/METs channels |
| D4 | No CGM in window ("reduced-sensor mode") | mask all glucose; anchor = fasting glucose from profile with large `anchor_age_min`; optionally a fingerstick anchor when available |
| D5 | Meal information incomplete | replace macros by meal-type averages + flag |
| D6 | New patient | K = 0 personal meals; similarity prior only |
| D7 | Out-of-support meal | meal far from training meals (support score below threshold) |

**Deliverables:** table of error vs scenario, a curve of error vs dropout length, and the per-scenario interval table. Expect D4 error to be large; the point is that **the system says so**.

**Behaviour rules:** any D1–D7 flag changes the reliability label, widens the interval using the scenario-specific table, and shows the reason. D4 prints: "Estimate based on wearables and profile only — not suitable for treatment decisions." Aegis never claims to measure glucose without a CGM.

## 10. Uncertainty (decision D4)
| Option | Verdict |
|---|---|
| Quantile regression heads | Optional extra |
| Deep ensemble (3–5 seeds) | Only if time permits |
| MC dropout | Weakly calibrated; skip |
| **Split conformal on absolute residuals per horizon step, per scenario** | **Chosen** — simple, model-agnostic, checkable |
Procedure: fit on calibration patients; for each scenario and horizon step compute the (1−α) quantile of |residual|; store `uncertainty_table.json`; interval = prediction ± quantile. Check **empirical coverage on test patients** per scenario. Caveat: guarantees assume exchangeability; patient shift can break them, hence the coverage report. If coverage is poor, widen with an empirical multiplier and say so. Never label an uncalibrated band a "confidence interval".

**Reliability labels** (thresholds DATA-DEPENDENT, set from coverage/width results):
| Label | Rule (draft) |
|---|---|
| High confidence | D0; ≥ K_min personal meals; meal in support; HR present; interval width below w_low |
| Moderate confidence | one mild flag (short dropout, few personal meals, borderline support) |
| Low confidence — more data needed | D4, long dropout, out-of-support meal, missing meal info, or width above w_high |

## 11. Personalisation (differentiator 6C)
**Method — residual-curve adaptation:**
1. On training patients compute residuals of the global model per meal; learn a low-dimensional basis (PCA, r components, r from validation).
2. For a target patient with K earlier meals, fit coefficients `α` by ridge regression of their residuals on the basis, shrunk toward a **prior mean** `α0`.
3. Adapted forecast = global forecast + basis·`α`.
4. Evaluate chronologically: K ∈ {0,1,3,5,10}; test on later meals only.

**Similarity (cold start):**
- Features: standardised age, sex, BMI, HbA1c, fasting glucose, fasting insulin, TG, HDL; once K>0 optionally add personal response summary.
- Similarity: Gaussian kernel on Euclidean distance, `k` neighbours (tune by leave-one-patient-out, k ∈ {3,5,7}).
- Prior `α0` = similarity-weighted mean of neighbours' fitted coefficients (neighbours exclude the target).
- Compare priors: (i) zero/global-mean prior, (ii) similarity prior.
- Report mean error and worst case for each K; if the similarity prior does not help, say so and present it as exploratory.

## 12. Scenario simulation (what-if)
| Scenario | Origin | Implementation |
|---|---|---|
| Change portion (amount consumed) | `model_driven` | modify effective macros; re-run model |
| Reduce/increase fat | `model_driven` | modify fat and ratios; re-run |
| Swap meal preset (Indian presets) | `model_driven` + support check | replace meal vector; if out of support → low confidence |
| Earlier/later meal time | `model_driven` | change hour features; limited by data support |
| Food sequencing (vegetables/protein first) | `assumption_driven` | scale the predicted early-window ΔG by a configurable factor with cited effect sizes |
| Post-meal walk (10/20/30 min) | `assumption_driven` | apply configurable attenuation to ΔG from the walk start |
Sources for sequencing priors (always shown as "assumption"): Shukla et al., *Diabetes Care* 2015 (food order and postprandial glucose/insulin); a 2024 study in participants with T2D reporting lower glucose and insulin incremental AUC with meal sequence (PMC11572438). `UNKNOWN—VERIFY` exact effect sizes before using any number in the UI.
**Exploratory data check (Track B if no time):** relate post-meal METs to residuals in CGMacros to see whether any walking-like signal exists; observational only.
Output per scenario: baseline vs scenario trajectory, differences in peak, time-to-peak, delayed-window mean, minutes above threshold, interval, origin label, reliability label.

## 13. Model improvement loop
Baseline → error analysis → hypothesis → experiment (logged) → evaluation on validation patients → decision (logged) → only then test patients for the final report. The test fold is **not** used for tuning.
